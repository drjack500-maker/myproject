# /text-to-slide — YouTube 台本 → スライド画像

入力: $ARGUMENTS

スクリプトは `python3 ${CLAUDE_SKILL_DIR}/scripts/text_to_slide.py <サブコマンド>` で実行する（標準ライブラリのみ・インストール不要）。
台本を「文」に分けて番号を振るのと画像生成はスクリプトが行い、**どこで区切るか・スライドに何を書くかはあなたが決める**。

## 手順

### 1. 台本を受け取る
- 引数が既存ファイルのパスなら、そのファイルを使う。
- 本文が直接貼られている場合は、Write ツールで一時ファイル（例: `/tmp/text-to-slide/<短い名前>.txt`）に**一字一句そのまま**保存する。
- 台本がなければ、台本を貼るかファイルを指定するよう頼んで終える。
- 台本以外の希望（デザイン・色・枚数・細かさ・縦長・安く速く など）があれば控えておく。

### 2. API キーを確認する
```bash
python3 ${CLAUDE_SKILL_DIR}/scripts/text_to_slide.py check
```
NG のときは表示された設定手順をユーザーに伝える。区切り（手順 3〜5）はキーなしでもできるので進め、最後に「キーを設定したら生成できる」と案内する。

### 3. 文に番号を振る
```bash
python3 ${CLAUDE_SKILL_DIR}/scripts/text_to_slide.py prepare <台本ファイル> --name "<動画の短い名前>"
```
出力フォルダ（`~/Downloads/スライド/<日時>_<名前>/`）、`[番号] 文` の一覧、推定尺、目安スライド枚数が表示される。
「200字を超える文」の注意が出たら（句読点のない台本）、**言葉は一切変えずに**句点だけ補ったファイルを作って prepare をやり直す。

### 4. 意味のまとまりで区切り、plan.json を書く（このスキルの中心）
下の「区切り方」「スライドの文言」に従って、表示された `plan.json の保存先` に Write で書く。

### 5. 検証する
```bash
python3 ${CLAUDE_SKILL_DIR}/scripts/text_to_slide.py render <出力フォルダ> --dry-run
```
エラーは plan.json を直して再実行。警告（タイトルが長い等）も原則直す。

### 6. 生成する
```bash
python3 ${CLAUDE_SKILL_DIR}/scripts/text_to_slide.py render <出力フォルダ>
```
- Bash の timeout は 600000 にする。30 枚を超えるときは `run_in_background` で実行して完了を待つ。
- 1 枚目を先に作り、2 枚目以降は 1 枚目をデザイン見本として添付して並列生成する（デッキの統一感のため）。
- 途中で止まっても、同じコマンドを再実行すればできていない分・変更した分だけ生成する。

### 7. 仕上がりを確認する
生成された画像を Read で見て（多いときも文字の多いスライドは必ず）、次をチェックする。
- 日本語の誤字・崩れた漢字・存在しない文字、plan にない余計な文字（ページ番号・英語ラベル等）
- 文字の欠け・はみ出し、1 枚だけデザインが違う
問題のあるスライドは plan.json を直して（文言を短く・平易な表記に、`visual` を具体的に、`notes` で禁止事項を指示）`--only <番号>` で作り直す。同じスライドの作り直しは 2 回まで。直らなければ報告する。

### 8. 報告する
保存先フォルダ、枚数、各スライドのタイトル一覧、`index.html`（台本と並べたプレビュー）と `台本対応表.md` の場所、作り直した・失敗したスライドを伝える。
「3 枚目の文言を変えて」のような修正依頼は、plan.json を編集して render を再実行すれば変更したスライドだけ作り直せる。

## 区切り方

**1 スライド = 1 メッセージ。** 視聴者がそのスライドを見ながらナレーションを聞いたときに、意味が完結している単位にする。

- 長さの目安は 1 枚あたり **15〜40 秒**（日本語でおよそ 80〜200 字）。prepare の「目安スライド枚数」を基準にする。「細かく」と言われたら 10〜20 秒、「ざっくり」なら 40〜60 秒。
- **切ってはいけない所**
  - 主張とその理由・根拠（「〜です。なぜなら〜」「〜からです。」）
  - 問いかけとその答え（「〜だと思いますか？」→「実は〜」）
  - 「つまり」「だから」「しかし」「ただ」「例えば」で始まる文と、その直前の文（短い具体例は元の主張と同じスライドに）
  - 一続きの手順・比較の途中
- **切る合図**
  - 話題の転換: 「さて」「では」「次に」「続いて」「2つ目は」「最後に」「まとめると」
  - 見出し行（【】や # で始まる行）、場面の変わり目
  - 列挙の各項目にそれぞれ説明が付いているときは 1 項目 1 枚（説明が一言ずつなら列挙全体で 1 枚）
- 冒頭の挨拶・フック・今日のテーマ紹介は 1 枚目（`title`）にまとめる。締めのチャンネル登録のお願い等は最後の 1 枚（`cta`）。
- 1 文だけのつなぎ・相づち（「はい。」「なるほど。」）や [BGM] などの演出指示は単独のスライドにせず、前後のどちらかに含める。
- 60 秒を超えるまとまりは、上のルールを守れる切れ目がないか探す。
- 全ての文をちょうど 1 回ずつ、順番どおりに含める（スクリプトが検証する）。

## スライドの文言

- 台本の文をそのまま貼らず、要点を短く言い換える。**台本にない数字・事実・固有名詞を足さない**（数字・名称は台本どおり）。
- `title`: 15 字前後（最大 20 字）。そのスライドの結論が一目で分かる言葉。
- `points`: 0〜4 個、各 20 字以内の短いフレーズ（体言止め推奨）。
- 画像モデルは長い文や難しい漢字で崩れやすいので、短く一般的な表記にする（「〜することができます」→「〜できる」）。
- `highlight`: アクセントカラーで強調したい語を 0〜2 個（title / subtitle / points に含まれる語）。
- `visual`: 何を描くかを具体的に（例: 「スマホ画面の中に小さく見えるサムネイル、虫眼鏡アイコン」）。実在の人物・ロゴ・商標は描かせない。
- 英語の台本なら文言も英語にする。

### layout の選び方

| layout | 使いどころ |
|---|---|
| `title` | 1 枚目。タイトル＋サブタイトル＋キービジュアル |
| `bullets` | 要点を 2〜4 個並べる（既定） |
| `steps` | 手順・順番・流れ |
| `comparison` | 比較（Before/After、NG/OK、A と B）。どちらに何を置くかは `visual` に書く |
| `big_number` | 数字や一言を大きく見せる（`points` の 1 個目が主役） |
| `quote` | 印象的な一言・格言（`points` の 1 個目が主役） |
| `diagram` | 関係図・サイクル・ピラミッドなど（形は `visual` に書く） |
| `image` | イラスト主体で、文字は少なめ |
| `summary` | まとめ・チェックリスト |
| `cta` | 最後のお願い（チャンネル登録・コメント・次の動画） |

### plan.json の形式

```json
{
  "deck_title": "クリックされるサムネイルの作り方",
  "style": "（任意）デザインの指示。省略時は白背景・紺文字・オレンジのアクセントの解説動画風",
  "slides": [
    {
      "from": 1, "to": 3,
      "layout": "title",
      "title": "クリックされるサムネの作り方",
      "subtitle": "今日から使える3つのコツ",
      "visual": "目を引くサムネイルが並ぶスマホ画面と、クリックする指"
    },
    {
      "from": 4, "to": 7,
      "layout": "bullets",
      "title": "文字は7文字以内",
      "points": ["スマホでは文字が小さい", "一瞬で読める量に"],
      "highlight": ["7文字"],
      "visual": "スマホの小さな画面で読めない長文サムネと、短い文字のサムネの対比",
      "notes": "（任意）追加の指示。例: 人物は描かない"
    }
  ]
}
```
`from` / `to` は prepare が表示した文番号（両端を含む）。`subtitle` `points` `highlight` `visual` `notes` `style` は省略可。

## デザインとオプション

- ユーザーがデザインを指定したら（例:「黒背景でかっこよく」「ピンク系でポップに」）、plan.json の `style` に背景色・文字色・アクセント色・フォントの太さ・イラストの雰囲気を具体的に書く（英語の方が安定する）。
- チャンネルのテンプレート画像など見本があれば `--style-image <画像パス>`（全スライドに添付される）。
- `render` のオプション:
  - `--model gemini-3.1-flash-image` … 安く速く（既定は文字描画が最も安定する `gemini-3-pro-image`）
  - `--size 4K` … 高解像度（既定 2K）／ `--aspect 9:16` … ショート動画向けの縦長
  - `--only 3,5-7` … 指定スライドだけ作り直す／ `--force` … 全部作り直す
  - `--no-style-ref` … 1 枚目を見本として添付しない
- 費用の目安（2026 年 10 月時点）: Pro 2K は 1 枚 約 $0.134、Flash 2K は約 $0.101。生成前にユーザーが費用を気にしていたら枚数×単価を伝える。
- 保存先の親フォルダは環境変数 `TEXT_TO_SLIDE_OUT` で変更できる。

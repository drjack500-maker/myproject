# 予約フォームの受信設定（Google Apps Script）

LPの予約フォームを、Google スプレッドシートの「予約台帳」で受け取る仕組みです。サーバー契約は不要で、Google アカウントがあれば無料で使えます。

## できること

- 予約リクエストを **予約台帳**（スプレッドシート）に自動で記録
- 医院の担当者へ **通知メール**
- メールアドレスを入力した方へ **自動返信メール**（希望日時・持ち物・アクセス）
- 台帳に「来院日時」「成約日時」「成約金額」を記入すると、**Google 広告のオフライン コンバージョン取り込み用シート** を作成
- **Meta 広告（Instagram・Facebook）のコンバージョンAPI** に予約（Lead）を送信（設定したときだけ。後述）
- 検索広告用LP（`all_on_4_004`）と Meta 広告用LP（`all_on_4_006`）の予約を、同じ台帳で受け付け（「流入ページ」列で区別）
- いたずら対策（見えない入力欄・送信までの時間・同じ電話番号の連続送信）。疑わしい送信は捨てずに「スパム疑い」として台帳に残し、通知メールは送りません
- 台帳の列は**見出し名で対応づけ**ます。列の並べ替えや独自の列を追加しても記録がずれません（足りない列は右端に自動で追加）

## 設置手順（15分ほど）

1. **医院の Google アカウント**で Google スプレッドシートを新規作成し、名前を「オールオン4 予約台帳」などにする
2. メニューの［拡張機能］→［Apps Script］を開く
3. 最初からある `コード.gs` の中身をすべて消し、このフォルダの **`Code.gs` の内容を貼り付け**
4. 冒頭の `SETTINGS` を編集
   - `notifyTo`：通知メールの送信先（例：`reception@example.jp`。複数はカンマ区切り）
   - `conversionNames`：Google 広告で作るコンバージョン名（後述）と同じ名前
5. 保存（💾）→ 上部の関数選択で **`setup`** を選んで［実行］→ 権限の確認画面で許可
   - 「このアプリは Google で確認されていません」と出た場合は［詳細］→［（プロジェクト名）に移動］で進めます（自分で作ったスクリプトのため）
6. 右上の［デプロイ］→［新しいデプロイ］→ 歯車から **「ウェブアプリ」** を選択
   - 次のユーザーとして実行：**自分**
   - アクセスできるユーザー：**全員**
7. ［デプロイ］を押し、表示された **ウェブアプリのURL（`https://script.google.com/macros/s/…/exec`）をコピー**
8. `lp/assets/js/main.js` の `CONFIG.formEndpoint` にそのURLを貼り付け、`npm run sync:006` で Meta 広告用LP（`lp-006/`）にも反映してから公開

```js
formEndpoint: 'https://script.google.com/macros/s/XXXXXXXX/exec',
```

### 動作確認

- ウェブアプリのURLをブラウザで開くと `ok` と表示されます
- LPから実際にテスト予約を1件送信し、台帳に行が増えること・通知メールが届くことを確認してください（ページを開いてから5秒以内の送信は、いたずら対策のため記録されません）

### スクリプトを修正したとき

［デプロイ］→［デプロイを管理］→ 鉛筆アイコン → バージョン「新バージョン」→［デプロイ］。URLは変わりません（「新しいデプロイ」を作るとURLが変わるので注意）。

## 予約台帳の使い方

| 列 | 記入する人 | 内容 |
|---|---|---|
| 受付日時〜ご質問・ご要望 | 自動 | フォームの入力内容 |
| **対応状況** | 受付スタッフ | 未対応 → 連絡済み → 予約確定 → 来院 → 成約／失注／キャンセル（プルダウン）。「スパム疑い」は自動で入ります |
| **来院日時** | 受付スタッフ | カウンセリングに来院した日時（例：`2026/10/02 15:00`） |
| **成約日時・成約金額** | 受付スタッフ | 治療が決まった日時と金額 |
| **対応メモ** | 受付スタッフ | 電話でのやりとりなど |
| 見出しパターン〜参照元 | 自動 | 広告の効果測定用（編集しないでください）。fbclid・fbc・fbp・イベントIDは Meta 広告用、「Meta送信」はコンバージョンAPIの送信結果 |

未対応の行は黄色、成約は緑で表示されます。**Web予約には当日中（できれば数時間以内）に電話**するのが、来院率を上げるいちばんの近道です。電話のトーク例やつながらないときの対応は [`docs/reception-manual.md`](../../docs/reception-manual.md) を参照してください。

## Google 広告に来院・成約を戻す（オフライン コンバージョン）

「予約は多いが成約しない」キーワードに広告費が流れるのを防ぐための設定です。

1. Google 広告 →［目標］→［コンバージョン］→［新しいコンバージョン アクション］→［インポート］→［その他のデータソースまたは CRM］→［クリックからのコンバージョンを追跡］
2. コンバージョン名を `SETTINGS.conversionNames` と同じにして2つ作成（例：「オールオン4 来院」「オールオン4 成約」）
3. 台帳に来院日時・成約日時・金額を記入 → スプレッドシートのメニュー［LP予約］→［広告CV取り込みシートを更新］
4. Google 広告の［コンバージョン］→［アップロード］→［スケジュール］で、ソースに Google スプレッドシートの「広告CV取り込み」シートを指定し、毎日取り込みに設定

> 取り込めるのは、広告のクリックから90日以内のコンバージョンです。gclid が空の行（自然検索・電話のみなど）は出力されません。
> 毎日自動で更新したい場合は、Apps Script の［トリガー］で `buildConversionSheet` を「時間主導型・日付ベース（毎日）」に設定してください。

## Meta 広告にも予約を送る（コンバージョンAPI・任意）

Instagram・Facebook のアプリ内ブラウザなどでは、ブラウザのピクセルだけでは予約完了が Meta に届かないことがあります。受信スクリプトから同じ予約を Meta に直接送ると、取りこぼしを補えます（ピクセルと同じイベントIDで送るため、二重には数えられません）。

1. Meta のイベントマネージャ → ピクセル →［設定］→［コンバージョンAPI］→［アクセストークンを生成］
2. Apps Script の［プロジェクトの設定］（歯車）→［スクリプト プロパティ］→ プロパティ `META_ACCESS_TOKEN`、値にトークンを貼り付けて保存（**コードには書かない**）
3. `SETTINGS.meta.pixelId` にピクセルIDを入れて保存 → エディタで関数 **`setup` を1回実行** し、追加の権限（「外部サービスへの接続」）を許可 → ［デプロイを管理］から新バージョンでデプロイ
   - 権限を許可しないままだと Meta への送信だけが失敗します（予約の受付・台帳・通知メールは通常どおり動き、「Meta送信」列にエラーが残ります）
4. 初回は `SETTINGS.meta.testEventCode` にイベントマネージャ［テストイベント］のコードを入れてテスト予約し、Lead が届くことを確認してから空に戻す

- 予約台帳の「Meta送信」列に「送信済み」またはエラー内容が記録されます。送信に失敗しても予約の受付には影響しません
- 送るのは広告クリックID（fbc）・ブラウザID（fbp）・ブラウザの種類・イベントID・ページのURLだけです。お名前・電話番号・メールは送りません（`sendHashedContact: true` にした場合のみハッシュ化して送ります。個人情報の取り扱いへの明記と同意の取得が必要です）
- スパム疑いの予約、照合に使える情報がない予約は送りません
- 詳しくは [`docs/measurement-setup.md` の7章](../../docs/measurement-setup.md#7-meta広告instagramfacebookの計測)

## 注意

- 予約台帳には個人情報が入ります。スプレッドシートの共有範囲は必要な職員だけにしてください
- 無料の Gmail アカウントの場合、送信できるメールは1日100通までです（通常の運用では十分です）
